   classes are in place and the 390 px layout test exists, but the
   verification was cut short by the host device rebooting under load.
   The single header, two-column product detail, cart drawer, and
   bottom-nav are all built for mobile. Re-verify on device when cool.
2. **[should] Customer photo gallery** — `partial`. Section omitted on
   purpose to avoid the original's photo assets. When the user supplies
   their own customer photos, drop them into the product detail page
   under the existing gallery.
3. **[could] Admin dashboard** — `no`. Not in scope for v1; the user
   manages orders from the in-DB `orders` / `order_items` views
   (`db/schema.ts`) and the email alert on new orders. Re-evaluate
   after the first 200 orders.
4. **[could] Online payment gateway** — `no`. COD only, as set in
   `replica/backend.md`. SSLCommerz integration is specced there and
   the route in `app/api/orders` already accepts `paymentMethod:
   "online"`; only the gateway handshake is missing.
5. **[could] Product search** — `no`. Header search icon routes to
   `/shop`; no full-text index. Easy add later (Postgres `pg_trgm` or
   a client-side fuzzy search across the cached catalogue).

## Behaviour diff

Walked the F01–F07 flows from `replica/test-plan.md`. Each line is
flow → original → clone → fix or keep.

- **F01 guest order (COD).** Original: home → shop → product → add to
  cart → cart drawer → checkout → confirmation. Clone: identical path
  and the same screens, plus a 4-step accessibility-clean flow at
  390 px. Keep.
- **F02 quick add from a card.** Original: click the card button, toast
  appears, cart count ticks up without leaving the page. Clone: same.
  Toast copy is "কার্টে যোগ হয়েছে" with a danger-tinted surface so
  it survives the new disabled-state contrast fix. Keep.
- **F03 direct order on the product page.** Original: scroll past the
  gallery, fill the inline form, submit. Clone: same. The inline form
  shares `OrderForm` with `/checkout` and reuses the same
  `idempotencyKey` + ref guard, so a double submit returns one order
  not two (see `replica/bugs.md` BUG-001). Keep, with the fix.
- **F04 track an order.** Original: enter the order number OR phone,
  look up. Clone: requires BOTH (the Sicily number-only path is a
  privacy hole — anyone with a receipt can read the address). Decision:
  keep the clone stricter, document it on `/track-order`. Better.
- **F05 wishlist.** Original: heart icon, persists per-device. Clone:
  same, localStorage, no account required. Keep.
- **F06 support handoff.** Original: WhatsApp float + /live-chat + a
  phone number. Clone: same three, plus a Bengali script on the
  WhatsApp template. Keep.
- **F07 content pages.** Original: about / faq / policies / blog.
  Clone: four pages seeded from `lib/data/seed.ts` (about, faq,
  policies, blog index + post). Keep, with a note to add real
  copy before launch.

Two intentional divergences worth calling out:
- **Track-by-number-and-phone instead of either** (F04) — better for
  the customer, matches what the original *should* be doing.
- **Rabbeya Furniture branding** end-to-end — by design, per
  `replica-brand` (next step).

## Layout diff

**Not run.** The `imgdiff.py` tool is in the skill folder and takes two
PNGs at the same viewport and state. Two reasons it is deferred:
1. The clone's `replica/clone-screens/` folder only has a README; the
   screenshots need a working dev server + headless Chromium, and this
   device's thermal protection has been rebooting under that workload
   (see `replica/bugs.md` footer).
2. The clone is a deliberate rebrand, so a re-run will deliberately
   diverge on colour, typography, and the brand mark; the layout score
   would be the only meaningful signal and it is gated on a stable
   machine.

To run the layout diff when the environment is ready:
```bash
python3 /root/.config/opencode/skills/replica-diff/imgdiff.py \
    replica/screens/S01.png replica/clone-screens/S01.png \
    --out replica/diffs/S01.png
# then
python3 /root/.config/opencode/skills/replica-diff/parity.py \
    replica/features.csv --visual replica/diffs/*.json --markdown \
    > replica/parity.md
```

## Verdict

**Not shippable, but close.** The single blocker is the
"Mobile-first responsive layout" must-have being `partial` — the
breakpoints and components are there, they have just not been
eyeballed on a real device at 390 px. Two ways to clear it:

- Quick: open `/`, `/shop`, `/p/<slug>`, the cart drawer, and
  `/checkout` in DevTools at 390 × 844 and confirm no horizontal
  scroll, no overlapping text, no clipped CTAs. Five minutes.
- Honest: rerun `bash e2e/run.sh` once on a cool device, the suite
  already covers the F01-E14 mobile layout case and the axe pass.

After that, the remaining five items (admin, online payments, search,
customer photos, layout screenshot diff) are **better-than-original**
work, not parity work, and belong in `/replica-entrepreneur` and
`/replica-brand`.
